# Test-only reviewer authority contract

The authority_contract module exercises authenticated envelopes with HMAC-SHA256 using fictional identities and a test harness registry. It is not a production credential verifier. The envelope binds issuer, key, attestation identifier, subject, role, credential reference, independence/conflict declarations, validity interval, exact evidence digest and exact record digest. Verification requires the expected subject, role and digests, an externally supplied scoped registry, revocation set and clock. All results deny scientific approval, freeze and inference. The real authority entry point always raises PermissionError.

The registry, revocation data and clock are trusted test inputs, not authenticated infrastructure. HMAC authenticates shared-secret possession, not a human identity or independently verifiable signature. A signed declaration does not establish its factual truth. Fixture keys must never be deployed. No real credentials or personal information belong in this repository.

Future production work requires approved credential issuers, independently verified identities, role separation, asymmetric signatures or equivalent trusted verification, secure trust-root provisioning, trusted time, revocation freshness and replay controls. It must bind each actual review/adjudication record and scientific approval to recomputed freeze evidence, verify distinct humans and independence, and address the candidate's non-independent authorship. No production trust root, multi-party approval aggregator or executable manifest is provided here. Existing freeze_evidence.authorize_freeze remains unchanged and always denies.
